# Rule 1 - 依系統功能切 feature 檔 [SHOULD]
- 各端點的 feature 檔依系統「功能」切分，同一功能的 Example 放進同一檔；不把整個端點塞進一個檔，也不一個 Example 一個檔。

## Good Example
- 後端依功能切成三個檔，每檔收同一功能的 Example。

```
backend/購物車/購物車.feature          @ac:003/購物車與運費:1-1、@ac:003/購物車與運費:1-2、@ac:003/購物車與運費:2-1
backend/優惠券/優惠券折抵.feature      @ac:003/折扣疊加與互斥:1-2、@ac:003/折扣疊加與互斥:1-3
backend/訂單/下單與付款.feature        @ac:003/訂單成立與付款:1-1、@ac:003/訂單成立與付款:2-1
```

## Bad Example
- 後端所有 Example 塞進同一個檔，讀者無法從檔名找到某個功能的情境。

```
backend/訂單/全部.feature              @ac:003/購物車與運費:1-1 … @ac:003/訂單成立與付款:2-1
```

# Rule 2 - 檔名用繁體中文呈現受測動作或面向 [SHOULD]
- 檔名用繁體中文，讓 PM 一看就知道檔內測的是哪個動作或面向。
- 不用英文、編號或「功能一」這類看不出內容的名稱。

## Good Example
- 檔名直接說出受測的動作或面向。

```
backend/購物車/購物車.feature
backend/優惠券/優惠券折抵.feature
backend/購物車/庫存不足.feature
```

## Bad Example
- 英文檔名與編號式檔名都看不出測的是什麼。

```
backend/購物車/cart.feature
backend/購物車/功能一.feature
backend/購物車/us2.feature
```

# Rule 3 - feature 檔放在與 step 模組同名的模組資料夾 [MUST]
- feature 檔放在 `specs/truth/features/<端點>/<模組>/`，模組名稱與該端 `<工作區>/tests/bdd/modules/<模組>/` 一致，讓 feature、dsl.md 與 step definition 一一對得上。
- 既有模組都不合適時才新增模組，名稱用繁體中文，並同時建立該模組的 dsl.md。

## Good Example
- 贈品功能的 feature 放進與 step 模組同名的 `贈品/`，該模組有自己的 dsl.md。

```
specs/truth/features/backend/贈品/滿額加贈.feature
specs/truth/features/backend/贈品/dsl.md
backend/tests/bdd/modules/贈品/
```

## Bad Example
- 第一個 feature 直接放在端點根目錄；第二個的模組資料夾用英文，對不到 step 模組 `贈品/`。

```
specs/truth/features/backend/滿額加贈.feature
specs/truth/features/backend/gift/滿額加贈.feature
```

# Rule 4 - 每個句型在端點內只定義一次 [MUST]
- 同一端點內每個句型只在一份 dsl.md 定義一次，寫在註冊它的 step 模組的 dsl.md；feature 檔可以使用同端任何一份 dsl.md 的句型。
- 尚未註冊的新句型，寫在第一個使用它的 feature 所屬模組的 dsl.md；要新增句型前，先在同端全部 dsl.md 找語意相同的既有句型。

## Good Example
- 贈品 feature 沿用訂單模組已定義的句型，只有新句型寫進贈品模組的 dsl.md。

```
backend/贈品/滿額加贈.feature 使用：
  Given "小芳" 的購物車有以下商品：          ← 定義在 backend/平臺共用/dsl.md
  Given 贈品 "運動水壺" 庫存剩 3 份          ← 新句型，定義在 backend/贈品/dsl.md
```

## Bad Example
- 為了讓贈品模組「自給自足」，把平臺共用已有的句型抄一份到贈品的 dsl.md，同一句型在端點內定義了兩次。

```
backend/平臺共用/dsl.md：`{會員暱稱} 的購物車有以下商品：`
backend/贈品/dsl.md：  `{會員暱稱} 的購物車有以下商品：`
```

# Rule 5 - 附錄共通規則只寫在平臺共用 [MUST]
- 「附錄：共通規則」只寫在 `<端點>/平臺共用/dsl.md`；其他模組的 dsl.md 不寫附錄，在檔頭寫明共通規則見 `specs/truth/features/<端點>/平臺共用/dsl.md` 的「附錄：共通規則」。

## Good Example
- 贈品模組在檔頭引用平臺共用的附錄。

```
# 後端 DSL：贈品
…共通規則見 `specs/truth/features/backend/平臺共用/dsl.md` 的「附錄：共通規則」。
```

## Bad Example
- 贈品模組另寫一份附錄，與平臺共用的資料列紀錄規則逐漸不一致。

```
# 後端 DSL：贈品
…
## 附錄：共通規則
- 資料列紀錄：只讀 gift_grants
```
