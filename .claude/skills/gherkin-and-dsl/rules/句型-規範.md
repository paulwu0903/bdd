# Rule 1 - When 只寫受測操作，journey 依操作順序交錯 [MUST]
- When 只寫這個 Example 要驗的受測操作，不混入登入、開頁這類前置動作；前置狀態一律寫在 Given。
- 原子 Example 寫一句 When。
- 帶 `@journey` tag 的端點 journey 依操作順序寫多段 When，每段 When 之後先接該段的 Then，再接下一段 When。

## Good Example
- 原子 Example 一句 When；端點 journey 每段 When 後緊接 Then。

```
@ac:003/購物車與運費:1-1
Example: 已有 2 件的 A100 再加入 1 件
  Given "小芳" 的購物車已有 "A100" 共 2 件
  When "小芳" 把 "A100" 加入購物車 1 件
  Then "小芳" 的購物車有 "A100" 共 3 件

@ac:003/訂單成立與付款:1-2 @ac:003/訂單成立與付款:1-3 @journey
Example: 同一筆訂單重複送出只成立一筆
  Given "小芳" 的購物車已有 "A100" 共 2 件
  When "小芳" 下單
  Then "小芳" 的訂單已成立，金額為 1200
  When "小芳" 再次送出同一筆訂單
  Then "小芳" 仍只有 1 筆訂單
```

## Bad Example
- 原子 Example 的 When 混進前置動作「登入」與開頁；journey 把所有 When 寫完才在最後 Then，中途哪一步出錯無從判斷。

```
@ac:003/購物車與運費:1-1
Example: 已有 2 件的 A100 再加入 1 件
  When "小芳" 登入
  And "小芳" 打開商品頁 "A100"
  And "小芳" 把 "A100" 加入購物車 1 件
  Then "小芳" 的購物車有 "A100" 共 3 件

@ac:003/訂單成立與付款:1-2 @ac:003/訂單成立與付款:1-3 @journey
Example: 同一筆訂單重複送出只成立一筆
  Given "小芳" 的購物車已有 "A100" 共 2 件
  When "小芳" 下單
  And "小芳" 再次送出同一筆訂單
  Then "小芳" 仍只有 1 筆訂單
```

# Rule 2 - 句子只用業務語言 [MUST]
- 步驟、步驟註解與 Data Table 值都用 PM 讀得懂的業務／驗證語意。
- 不出現技術詞：API、端點路徑、JSON、token、快照、HTTP、狀態碼、錯誤碼識別字、fixture、request／response、Promise、locator、World 等；技術語意只寫在 dsl.md 的實作語意欄。

## Good Example
- 句子講業務事實，打哪個端點、讀哪張表留給 dsl.md。

```
When "小芳" 把 "A100" 加入購物車
Then "小芳" 的購物車有 "A100" 共 1 件
```

## Bad Example
- 句子直接寫了端點、JSON 與狀態碼，PM 讀不懂。

```
When "小芳" 呼叫 POST /api/cart/items 帶 {"sku": "A100"}
Then 回應 status 為 201 且 JSON 的 items 長度為 1
```

# Rule 3 - 語意完全一致就用同一句型 [MUST]
- 兩句語意 100% 一致時寫成同一句型，只換參數值；不另造只差幾個字的近似句型。

## Good Example
- 兩個 Example 的「加入購物車」語意相同，共用同一句型。

```
Example A：When "小芳" 把 "A100" 加入購物車
Example B：When "阿德" 把 "B200" 加入購物車
dsl.md：`{會員暱稱} 把 {商品編號} 加入購物車`
```

## Bad Example
- 同一個動作換了說法就多出一個句型。

```
Example A：When "小芳" 把 "A100" 加入購物車
Example B：When "阿德" 將商品 "B200" 放進購物車
dsl.md：`{會員暱稱} 把 {商品編號} 加入購物車`、`{會員暱稱} 將商品 {商品編號} 放進購物車`
```

# Rule 4 - 複合句拆成可重用的核心句型 [SHOULD]
- 一句裡包了兩件可以各自成立的事時，拆成兩句核心句型，以 `And` 串接；Given 與 Then 可自由用 `And`。
- 拆開後的句型要能在其他情境重用；拆了反而無法單獨成立的不拆。

## Good Example
- 「會員存在」與「購物車內容」各自是核心句型，其他情境可以單獨重用。

```
Given 會員 "小芳" 已註冊
And "小芳" 的購物車已有 "A100" 共 2 件
```

## Bad Example
- 兩件事黏成一句，只想要「已註冊」的情境就得再造一個句型。

```
Given 會員 "小芳" 已註冊且購物車已有 "A100" 共 2 件
```

# Rule 5 - 參數名稱用繁體中文且與規格用詞一致 [MUST]
- 句型的 `{參數}` 名稱用繁體中文，用詞與規格一致；同一個概念在各句型用同一個名稱。

## Good Example
- 規格叫「商品編號」「會員暱稱」，句型照用。

```
`{會員暱稱} 把 {商品編號} 加入購物車`
`{會員暱稱} 的購物車有 {商品編號} 共 {數量} 件`
```

## Bad Example
- 一個用英文 sku，一個自創「品項代號」，與規格的「商品編號」不一致。

```
`{會員暱稱} 把 {sku} 加入購物車`
`{會員暱稱} 的購物車有 {品項代號} 共 {數量} 件`
```

# Rule 6 - 字串參數加雙引號、整數不加 [MUST]
- 型別為字串的參數值寫在雙引號內；整數直接寫數字，不加引號。
- Data Table 與 Examples 的儲存格一律不加引號。

## Good Example
- 暱稱與商品編號加引號，件數不加；表格值不加引號。

```
Given "小芳" 的購物車已有 "A100" 共 2 件
And 以下商品的庫存為：
  | 商品編號 | 庫存 |
  | A100     | 5    |
```

## Bad Example
- 件數被加了引號、商品編號沒加；表格值多了引號。

```
Given "小芳" 的購物車已有 A100 共 "2" 件
And 以下商品的庫存為：
  | 商品編號 | 庫存 |
  | "A100"   | 5    |
```

# Rule 7 - 錯誤以業務原因表達 [MUST]
- 被拒絕的結果在句子裡寫業務原因（如「庫存不足」「優惠券已過期」），不寫錯誤碼；原因對到哪個錯誤碼寫在 dsl.md 的預設參數。

## Good Example
- 句子寫業務原因，錯誤碼對照放在 dsl.md。

```
Then "小芳" 的 "下單" 因 "庫存不足" 被拒絕，沒有任何改變
dsl.md 預設參數：• `拒絕原因對照`：字串；預設為 庫存不足＝OUT_OF_STOCK、優惠券已過期＝COUPON_EXPIRED。
```

## Bad Example
- 錯誤碼直接寫進句子。

```
Then "小芳" 下單收到 OUT_OF_STOCK
```

# Rule 8 - Given 建構 When 之前的完整目標狀態 [MUST]
- 以 1..* 句 Given 建構 When 之前的目標狀態；When 與 Then 會用到的每個狀態元素（會員、商品、庫存、購物車、優惠券…）都要有一句 Given 建立，不靠 step definition 暗中準備。
- 時間參數、時鐘位置與期間會發生的定期活動也寫成明確的 Given，不藏在註解裡。

## Good Example
- 會員、購物車內容、庫存與優惠券期限都各有一句 Given，到期時刻寫成明確的 Given。

```
Given 會員 "小芳" 已註冊
And "小芳" 的購物車已有 "A100" 共 2 件
And 以下商品的庫存為：
  | 商品編號 | 庫存 |
  | A100     | 1    |
And 優惠券 "NEW100" 的到期時刻為 "今天 23:59"
When "小芳" 以優惠券 "NEW100" 下單
```

## Bad Example
- When 用到的庫存與優惠券沒有任何 Given 建立；到期時刻藏在註解裡。

```
Given 會員 "小芳" 已註冊
And "小芳" 的購物車已有 "A100" 共 2 件
# 優惠券今天 23:59 到期
When "小芳" 以優惠券 "NEW100" 下單
```

# Rule 9 - 前端 Given 直接準備狀態 [SHOULD]
- 前端的 Given 透過 API 或 fixture 直接把系統準備成目標狀態，再開啟對應畫面；不靠一步步點畫面堆出狀態。
- 例外：Example 的受測行為本身就是那段畫面流程時，保留由畫面操作建立的 Given，並在 dsl.md 的實作語意寫明原因。
- Given 句子描述目標狀態，不描述點擊過程。

## Good Example
- 句子描述「購物車已有商品」這個狀態，實作語意寫明以 API 準備後開頁。

```
Given "小芳" 的購物車已有 "A100" 共 2 件
dsl.md 怎麼做：以會員身分呼叫加入購物車操作兩次，再把身分放進瀏覽器並開啟購物車頁。
```

## Bad Example
- 受測行為是結帳，Given 卻一步步點畫面加商品，句子也在描述點擊。

```
Given "小芳" 打開商品頁 "A100"
And "小芳" 按下加入購物車
And "小芳" 再按一次加入購物車
And "小芳" 打開購物車頁
```
