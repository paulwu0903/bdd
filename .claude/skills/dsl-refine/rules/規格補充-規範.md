# Rule 1 - 只補 acceptance 沒涵蓋的 spec 需求 [MUST]
- 逐條比對 spec.md 的 FR、NFR 與 Edge Cases 和 acceptance 的檢查點：已被某個檢查點完整涵蓋的不另寫；只涵蓋一部分的，只補沒涵蓋的那部分。
- acceptance 只寫核心流程，沒寫到不代表不用測；被擠掉的需求由本步補成端點 Example。

## Good Example
- FR-007 的「超過收貨後 7 天不得退貨」已在 acceptance 檢查點中，不另寫；同一條的「退貨運費由會員負擔」沒有任何檢查點寫到，只補這一部分。

```
FR-007 超過 7 天不得退貨    → 已由 @ac:退貨與退款:2-1 涵蓋，不另寫
FR-007 退貨運費由會員負擔    → 補寫：@spec:FR-007 Example: 退貨 1 件越野跑鞋扣除退貨運費
```

## Bad Example
- 把 acceptance 已涵蓋的需求再從 spec 寫一次，同一個行為出現兩組 Example；或反過來只看 acceptance，FR-012 的付款失敗通知完全沒有 Example。

```
@spec:FR-007 Example: 收貨 8 天後申請退貨被拒絕  ← 與 @ac:退貨與退款:2-1 重複
FR-012 付款失敗通知                            → （無任何 Example）
```

# Rule 2 - 可在端點觀察的 NFR 才寫成 Example，純量測的只回報 [MUST]
- NFR 的結果能在單一端點的一次操作中觀察到（如重送付款不重複扣款、只用鍵盤可完成結帳、某寬度下不出現水平捲動），照樣推導成端點 Example。
- 需要壓力測試、統計或使用者研究才能判定的 NFR 與 Success Criteria（如 1000 人同時結帳的 p95、首次結帳成功率 ≥ 95%），不寫成 Example，列入回報的「純量測需求」。

## Good Example
- 重送付款不重複扣款能以一次重送觀察，寫成 Example；1000 人同時結帳要壓測，列入回報。

```
NFR-003 重送不重複扣款      → @spec:NFR-003 Example: 以同一付款識別碼重送後只扣款 1 次
NFR-002 1000 人結帳 p95 ≤ 300 毫秒 → 回報：純量測需求，不寫 Example
```

## Bad Example
- 把壓測寫成 BDD Example，step definition 無法真的產生 1000 人負載，只會變成假通過。

```
@spec:NFR-002
Example: 1000 位會員同時結帳
  When 1000 位會員同時送出訂單
  Then 每位會員都在 300 毫秒內收到結果
```

# Rule 3 - 以 `@spec:<編號>` 追溯，Edge Case 以它引用的編號追溯 [MUST]
- 從 spec 補出的端點 Example，正上方帶 `@spec:<FR 或 NFR 編號>`，例如 `@spec:FR-012`；同時涵蓋多個編號時各帶一個。
- Edge Cases 沒有自己的編號，以該條 Edge Case 寫的「依 FR-xxx／NFR-xxx」作為追溯編號。

## Good Example
- Edge Case「付款逾時後會員再按一次付款……依 NFR-003 只扣款一次」以 NFR-003 追溯。

```
@spec:NFR-003
Example: 付款逾時後再按一次付款
```

## Bad Example
- 自創 Edge Case 編號，spec 中找不到；或沒有任何追溯 tag。

```
@spec:EC-07
Example: 付款逾時後再按一次付款

Example: 付款逾時後再按一次付款
```

# Rule 4 - 數值與文案取自 spec 與已拍板決策，與 acceptance 衝突時以 acceptance 為準 [MUST]
- 從 spec 補出的 Example，數值、文案與行為取自 spec.md 的 FR、NFR 與 Assumptions 中已拍板的決策；Assumptions 寫明「使用者於某階段釐清」的決策優先於同條 FR 較早的寫法。
- spec 與 acceptance 寫法不一致時，依 acceptance 撰寫，並在回報中列出 spec 應修正之處。

## Good Example
- Assumptions 記載 system-analysis 階段拍板「退款一律退回原付款方式，不轉購物金」，Example 依此撰寫。

```
@spec:FR-008
Then "小芳" 的退款 360 元退回 "信用卡"
```

## Bad Example
- 依 FR-008 較早的模糊寫法「退款給會員」自行假設轉成購物金，與已拍板的決策相反。

```
Then "小芳" 的購物金增加 360
```
