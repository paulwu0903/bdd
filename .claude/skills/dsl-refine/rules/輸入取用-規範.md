# Rule 1 - 依來源的取用範圍讀取 [MUST]
- 每份上游只讀下表規定的範圍；不讀的來源一律不讀，避免把澄清前的寫法或與本步無關的內容帶進推導。

| 來源 | 取用範圍 |
|---|---|
| plan 的 `features/acceptance/*.feature` | 全讀，含已澄清標籤 |
| plan 的 spec.md | 只讀 FR、NFR、Success Criteria、Edge Cases、Assumptions 與既有需求異動；不讀 Input 原文與 User Story 敘述 |
| plan 的 plan.md | 只讀「系統介面的盤點」 |
| plan 的 truth-delta.md | 只讀 requirements、contracts、data、features 四段 |
| `specs/truth/contracts/`（openapi.yaml、asyncapi.yaml） | 按需讀分配到的 operation、schema、錯誤碼、事件 |
| `specs/truth/data/schema.dbml` | 按需讀分配到的資料表與欄位 |
| plan 的 `ui/frontend.md` | 按需讀分配到的畫面段落（四態、版面文字、欄位驗證、互動與呼叫表），不讀視覺風格 |
| plan 的 research.md | 只讀狀態存放位置、即時同步方式、時間與亂數的可控方式三類已定案決策 |
| `specs/truth/techstack.md` | 只讀測試與 BDD 框架 |
| `specs/truth/features/<端點>/` | 全部 dsl.md 的句型欄與業務語意；全部 feature 檔的 Feature、Rule、Example 標題與追溯 tag；find_impact 候選與本次要修改的 feature 檔與 dsl.md 列讀全文 |
| plan 的 `ui/prototype/`、其他 plan 目錄、原始碼 | 不讀 |

## Good Example
- 只讀盤點段落、三類決策與 spec 的需求條目，prototype 與 User Story 敘述不讀。

```
plan.md        → 「系統介面的盤點」
research.md    → 狀態存放、即時同步、時間與亂數可控方式
spec.md        → FR、NFR、Success Criteria、Edge Cases、Assumptions、既有需求異動
truth/features → 句型欄、業務語意、標題與追溯 tag；候選檔讀全文
prototype/     → 不讀
```

## Bad Example
- 讀了 prototype 的 HTML，把雛形的 class 名稱寫進實作語意；讀了 plan.md 的 Source Code 樹，在 dsl.md 裡指向原始碼檔案；只讀了本次要寫的模組 dsl.md，沒看到別的模組已有同義句型。

```
prototype/room.html class="chat-input" → 實作語意寫「找到 .chat-input」
plan.md Source Code → 實作語意寫「呼叫 backend/src/routes/orders.ts」
只讀 backend/贈品/dsl.md → 另寫一個與 backend/平臺共用/dsl.md 同義的句型
```

# Rule 2 - 契約、資料表與畫面只讀分配到的部分 [SHOULD]
- 只讀職責分配後該端點用得到的 operation、畫面段落與資料表，不整份載入。

## Good Example
- 後端只分配到送出訂單與付款，只讀這兩個 operation 與相關資料表。

```
openapi.yaml → createOrder、payOrder 與其 schema、錯誤碼
schema.dbml  → orders、order_items、products
```

## Bad Example
- 整份 openapi.yaml 與 schema.dbml 都讀進來，含退貨、會員等完全沒分配到的部分。

```
openapi.yaml → 全部 operation
schema.dbml  → 全部資料表
```

# Rule 3 - 找不到 BDD 框架時詢問 [MUST]
- techstack.md 沒寫該端點的 BDD 框架時，停下向使用者詢問，不從 package.json 或其他檔案推測。

## Good Example
- techstack.md 只有 vitest 與 @playwright/test，沒有 BDD 框架，向使用者詢問。

```
techstack.md：vitest、@playwright/test
→ 詢問：後端與前端的 BDD 框架分別是什麼？
```

## Bad Example
- 從 package.json 看到 cucumber 就直接採用。

```
backend/package.json："bdd": "cucumber-js" → 採用 cucumber-js
```
