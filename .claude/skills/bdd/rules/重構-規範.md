# Rule 1 - 小步改動，每步之後保持全綠 [MUST]
- 一次只做一種整理（抽 helper、改名、移動檔案、抽 parameter type），做完立刻重跑範疇。
- 變紅就撤回或修正這一步，回到全綠才做下一步；不在紅燈狀態下繼續整理。

## Good Example
- 每一步都重跑，變紅就撤回。

```
1. 抽出 seedRoomInRound() helper → 重跑範疇：全綠
2. 合併兩個 driver 的重複查詢 → 重跑範疇：2 個紅 → 撤回這一步
3. 把 {房間代碼} 抽成 parameter type → 重跑範疇：全綠
```

## Bad Example
- 一次改完所有檔案才跑，紅了也分不出是哪一步造成的。

```
抽 helper、合併 driver、改檔名、抽 parameter type 一起改 → 重跑範疇：7 個紅
```

# Rule 2 - 句型與可觀察行為不變 [MUST]
- step expression 與 dsl.md 句型維持一對一，不合併、不拆分、不改寫成 dsl.md 沒定義的寫法。
- 產品碼的可觀察行為不變：回應、畫面、資料列都與重構前相同。
- 只有修改 dsl.md 句型才能做的整理，屬於上游，依上游缺口判準交還。

## Good Example
- 兩個句型的實作重複，抽成共用 helper，兩個 step expression 照舊。

```ts
Then('{玩家暱稱} 的聊天紀錄共 {數量} 則', async function (this: ChatWorld, p: string, n: number) {
  await assertHistory(this, p, rows => assert.equal(rows.length, n))
})
Then('{玩家暱稱} 讀到以下聊天紀錄：', async function (this: ChatWorld, p: string, table: DataTable) {
  await assertHistory(this, p, rows => assert.deepEqual(rows, toMessages(table)))
})
```

## Bad Example
- 為了減少 step，把兩個 dsl.md 句型合成一個帶可選文字的 expression，句型不再一對一。

```ts
Then('{玩家暱稱} (的聊天紀錄共 {數量} 則/讀到以下聊天紀錄：)', ...)
```

# Rule 3 - 重複的佈置與斷言抽到 helper 或 driver [SHOULD]
- 多個 step 重複的佈置、查詢或斷言程式，抽成 helper 或 driver 方法，在程式語言層組合；不從 step 呼叫 step。

## Good Example
- 三個 Given 都要先建立對局到第 N 輪，抽成一個 driver 方法。

```ts
await this.driver.seedRoomInRound(room, host, guest, round)
```

## Bad Example
- 同一段建房、加入、開局的程式碼在三個 step 裡各複製一份。

```ts
Given('...對局到第 {輪數} 輪', async function (...) { await createRoom(...); await join(...); await start(...); /* ... */ })
Given('...尚未開始遊戲', async function (...) { await createRoom(...); await join(...); /* ... */ })
```

# Rule 4 - 尚未抽出的領域名詞在重構時抽成 parameter type [SHOULD]
- red 時還沒定義成 parameter type 的領域名詞（暱稱、房間代碼、拒絕原因），在 refactor 時抽出，讓轉換規則只寫一次。

## Good Example
- 多個 step 各自解析房間代碼，重構時抽成 parameter type。

```ts
defineParameterType({ name: '房間代碼', regexp: /"(\d{4})"/, transformer: (code: string) => code })
```

## Bad Example
- 每個 step 自己去掉引號、檢查四位數，規則散落在多處。

```ts
Given('房間 {string} 的聊天區還沒有訊息', async function (this: ChatWorld, raw: string) {
  const code = raw.replace(/"/g, ''); if (!/^\d{4}$/.test(code)) throw new Error('bad code')
})
```

# Rule 5 - 產品碼只整理本範疇 green 動到的部分 [MUST]
- 產品碼的重構範圍限於本範疇 green 新增或修改的檔案與函式；範疇外的產品碼即使看到可改之處，也只列入回報。

## Good Example
- 只整理 green 為靜音新增的服務函式，其他看到的問題列入回報。

```
整理：backend/src/services/chat.ts 的 visibleMessages、isMutedBy
回報：backend/src/services/room.ts 的 leaveRoom 有重複查詢（範疇外，未修改）
```

## Bad Example
- 順手重寫範疇外的房間服務，範疇的 BDD 抓不到這些改動可能造成的退步。

```
整理：chat.ts（範疇內）+ room.ts、match.ts、player.ts 全面改寫（範疇外）
```
