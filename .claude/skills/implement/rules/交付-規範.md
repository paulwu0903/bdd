# Rule 1 - commit 範圍只含本 plan、truth 與本次程式碼 [MUST]
- commit 只包含：本 plan 目錄（`specs/plans/<NNN>-<name>/`）、`specs/truth/` 的異動，以及本次任務新增或修改的程式碼與設定。
- 不包含產生出來的檔案（建置輸出、`.features-gen`、覆蓋率、測試報告）、暫存與 scratch，以及其他 plan 目錄的異動；這些檔案若出現在工作目錄的變更清單中，列出並排除。
- 詢問使用者時一併列出將要 commit 的檔案清單。

## Good Example
- 只加入本 plan、truth 與本次程式碼，產生出來的報告排除並說明。

```
git add specs/plans/004-full-amount-gift specs/truth backend/src backend/tests backend/db frontend/src frontend/tests
排除：frontend/test-results/、backend/reports/（測試產物）
```

## Bad Example
- 以 `git add -A` 把測試報告與其他 plan 的半成品一起 commit。

```
git add -A
```

# Rule 2 - commit message 依 truth-delta 摘要 [MUST]
- 第一行為 `<plan 目錄名>: <一句話摘要>`。
- 內文依 truth-delta 的各段列出 ADD、MODIFY、DELETE 的數量與重點，以及完成的任務數與最後一次全量驗證結果。
- 結尾加上專案規定的署名行。

## Good Example
- 一眼看出這次交付改了哪些 truth。

```
004-full-amount-gift: 滿額加贈與移除取消贈品

requirements: ADD 2, MODIFY 1, DELETE 1
contracts: ADD 2, MODIFY 2, DELETE 1（cancelGift）
data: ADD 2, DELETE 1
features: ADD 2, MODIFY 2, DELETE 1
tasks: 42/42；truth 套件 backend 118 passed、frontend 71 passed；check_trace OK

Co-Authored-By: …
```

## Bad Example
- 只寫「update」，之後無法從歷史看出這次交付的內容。

```
update
```

# Rule 3 - 只 commit，不 push、不開 PR [MUST]
- 交付只建立本機 commit；push、開 PR 與 merge 都屬於對外動作，由使用者自行決定，不在本 skill 執行。

## Good Example
- commit 完成後回報雜湊值，提醒 push 由使用者決定。

```
commit 3f2a9c1 已建立；尚未 push
```

## Bad Example
- commit 後自動 push 並開 PR。

```
git push origin 004-full-amount-gift && gh pr create …
```
