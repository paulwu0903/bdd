# Rule 1 - 只呈現畫面與直接互動 [MUST]
- 雛形只用來看畫面長什麼樣、操作起來是什麼感覺：用頁面內的假資料直接改畫面。
- 不串接後端，也不寫模擬後端的程式（以 operationId 命名的假 API、延遲 Promise、事件模擬器、重連退避等）；畫面上看得到的延遲效果（如 8 秒後出現改價提示）用 `setTimeout` 直接呈現。

## Good Example
- 按下加號直接改假資料並重畫。

```js
// Increase quantity in the fake cart and re-render.
item.quantity += 1;
saveCart(cart);
render();
```

## Bad Example
- 為雛形寫了一層假後端，程式量大增，卻不會讓畫面看起來更像。

```js
const api = {
  updateCartItemQuantity: (id, q) => serve(() => { /* ... */ }, latency()),
};
```

# Rule 2 - 外觀就是真產品 [MUST]
- 畫面上不放說明文字、註記、標籤或 lorem ipsum；所有文案寫成正式上線的文案。

## Good Example
- 文案就是使用者會看到的字。

```html
<button class="btn primary">前往結帳</button>
```

## Bad Example
- 畫面上出現給 review 者看的註記。

```html
<p class="note">（此處為結帳按鈕，點擊後呼叫 createOrder）</p>
```

# Rule 3 - 雙擊即可開啟 [MUST]
- 只用 HTML、CSS 與原生 JS，不需要 build 或伺服器，雙擊即可開啟；外部資源只允許 Google Fonts 的 stylesheet，並設定後備字型。
- 入口為 `index.html`；需要換頁時拆成多個 HTML，共用的樣式與程式放在 `assets/`，以相對路徑引用。
- 「外部資源只允許 Google Fonts」是雛形為了雙擊可開的限制；frontend.md 的字型載入方式依 research.md 的決策寫，不沿用本條。

## Good Example
- 相對路徑引用共用檔，`file://` 下也能載入。

```html
<link rel="stylesheet" href="assets/style.css">
<script src="assets/app.js"></script>
```

## Bad Example
- 依賴 build 與絕對路徑，雙擊打開是空白頁。

```html
<script type="module" src="/src/main.tsx"></script>
```

# Rule 4 - 色彩變數與基本可用性 [SHOULD]
- 色彩以 CSS 變數定義在 `:root`，名稱與色碼和 frontend.md「視覺風格」的色彩 token 一致。
- 寬 375px 時沒有水平捲動；只用鍵盤可以完成主要流程，焦點清楚可見。

## Good Example
- 變數名稱與 frontend.md 的 token 相同。

```css
:root { --grass: #5DA130; --redstone: #C0392B; }
```

## Bad Example
- 色碼直接寫死在各處，和 frontend.md 的 token 對不上。

```css
.btn.primary { background: #5da130; }
.item.soldout { border-color: red; }
```

# Rule 5 - 既有畫面的雛形以現行程式為基準重做 [MUST]
- 修改既有的畫面，依現行前端程式（樣式 token、元件、頁面結構與文案）重新做出受影響頁面的靜態版本，再加上本次的修改；不複製先前 plan 的 `ui/prototype/`。
- 只做受影響的頁面，未受影響的頁面不重做；色彩變數名稱與色碼取自現行的樣式 token 檔。

## Good Example
- 聊天區依現行的 `tokens.css`、`chat.css` 與 `ChatMessageList.tsx` 的結構重做對戰畫面，再加上表情回應列與 500 字提示。

```
prototype/game.html          # 依 frontend/src/pages/GamePage.tsx 與 ChatPanel.tsx 的結構重做，加上表情回應列
prototype/assets/style.css   # :root 色彩變數取自 frontend/src/styles/tokens.css
```

## Bad Example
- 直接複製 002 的 prototype 再修改，002 交付後程式改過的版面與文案都不會反映，review 看到的畫面與真實產品不符。

```
cp -R specs/plans/002-pvp-1a2b-chat/ui/prototype specs/plans/003-chat-reactions/ui/prototype
```
